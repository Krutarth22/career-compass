# Tutorial Series with Runnable Samples

## Production Workflow Mirrored
1. Choosing tutorial topics from real developer questions, not a feature list
2. Writing for a specific reader with a specific goal and prior knowledge
3. Keeping code samples runnable, tested, and copy-paste correct
4. Publishing where developers search, with measurable engagement
5. Iterating from comments, issues, and analytics

## What You'll Build
A four-part tutorial series on a developer tool, API, or library you
know well (an open-source project is ideal), each part solving one
concrete task for a defined reader, with a companion repository of
runnable samples tested in CI, published on a platform with analytics,
and a revision pass based on the first two weeks of reader feedback and
metrics.

## Student-Scope Notes
- Pick topics by mining the project's issues, forum, and search
  questions; document that research.
- Each tutorial should take a reader under thirty minutes and end with
  something working.
- Publish on the project's docs site if they accept contributions, or a
  blog platform with analytics otherwise.

## Steps
1. Research what developers struggle with: read fifty issues or forum
   threads, list recurring questions, and choose four tutorial topics
   with a stated reader and goal for each.
2. Write the outline for each: prerequisites, the steps, the working
   result, and the common mistakes to address.
3. Build the sample code for all four in a repository with a test that
   runs each sample in CI.
4. Write the first tutorial, then have someone matching the reader
   profile follow it cold and note every stumble. Revise.
5. Write and cold-test the remaining three.
6. Publish with consistent structure, code blocks that match the tested
   samples exactly, and links between parts.
7. Track views, completion signals, and comments for two weeks, and
   collect questions that came in.
8. Revise based on the data and feedback, and write up the topic
   research, the cold-test findings, and the metrics.

## Extension Ideas
- Add a video walkthrough for the most-viewed tutorial.
- Translate one tutorial into a second language.
- Contribute the series to the project's official documentation.
- Add an interactive sandbox version of one sample.

## Skills Demonstrated
- Developer-question research and topic selection
- Task-focused technical writing tested with real readers
- Runnable, CI-tested sample code
- Publishing with measurement and iteration

## Industry Relevance

Developer Tools, Cloud Platforms, API Companies. Developer relations teams in these sectors are measured on whether content gets developers to a working result, and hiring managers ask for published work with evidence it helped. A tested series with cold-run revisions and engagement data is that evidence.
